# Тестовый стенд X-Forwarded-For с цепочкой nginx

## Описание проекта

Стенд состоит из трёх nginx-серверов в режиме обратного прокси и одного приложения, отвечающего по HTTP. Все сервисы запускаются в docker-compose.

**Цель:** Продемонстрировать корректную обработку заголовка `X-Forwarded-For` при прохождении запроса через цепочку прокси-серверов и защиту от подделки этого заголовка.

## Архитектура

**Сервисы и их адреса:**

| Сервис    | Внешний порт | Внутренний IP   | Роль             |
|-----------|-------------|-----------------|------------------|
| nginx1    | 8081        | 10.2.0.10       | Первый прокси    |
| nginx2    | 8082        | 10.2.0.11       | Второй прокси    |
| nginx3    | 8083        | 10.2.0.12       | Третий прокси    |
| nginx-web | -           | 10.2.0.13:8080  | Приложение       |

**Поддерживаемые маршруты:**

| Маршрут                                         | URL для теста            |
|-------------------------------------------------|--------------------------|
| пользователь -> nginx1 -> nginx-web              | localhost:8081/direct    |
| пользователь -> nginx2 -> nginx-web              | localhost:8082/direct    |
| пользователь -> nginx3 -> nginx-web              | localhost:8083/direct    |
| пользователь -> nginx1 -> nginx2 -> nginx3 -> nginx-web   | localhost:8081/chain     |
| пользователь -> nginx1 -> nginx2 -> nginx3 -> nginx-web   | localhost:8081/          |

## Логика работы

### Формирование цепочки IP-адресов

1. **Первый nginx в цепочке** (тот, на который пришёл запрос от пользователя):
   - Очищает заголовок `X-Forwarded-For` директивой `proxy_set_header X-Forwarded-For ""`
   - Формирует новый заголовок из IP клиента (`$remote_addr`) и своего IP

2. **Последующие nginx в цепочке**:
   - Получают существующий заголовок через переменную `$http_x_forwarded_for`
   - Добавляют свой IP в конец цепочки

3. **Приложение**:
   - Получает итоговый заголовок с полной цепочкой IP-адресов
   - `Remote-Addr` содержит IP последнего прокси
   - Возвращает JSON с полученными заголовками

### Защита от подделки IP

- Любой пользователь может добавить заголовок `X-Forwarded-For` в свой запрос
- Первый nginx в цепочке всегда очищает этот заголовок
- Таким образом, поддельные IP-адреса никогда не попадают в приложение
- Защита работает независимо от того, на какой nginx пришёл запрос

## Как тестировать

### Одиночный прокси (nginx[1-3])

**Цель:** маршрут `пользователь -> nginx1 -> nginx-web`

**Команда:**
```bash
curl -s http://localhost:8081/direct
```

**Результат:**
```json
{
    "X-Forwarded-For": "10.2.0.1, 10.2.0.10",
    "Remote-Addr": "10.2.0.10"
}
```

### Цепочка из трёх прокси

**Цель:** маршрут `пользователь -> nginx1 -> nginx2 -> nginx3 -> nginx-web`

**Команда:**
```bash
curl -s http://localhost:8081/chain
```

**Результат:**
```json
{
    "X-Forwarded-For": "10.2.0.1, 10.2.0.10, 10.2.0.11, 10.2.0.12",
    "Remote-Addr": "10.2.0.12"
}
```

### Проверка подмены заголовка

**Цель:** маршрут `пользователь -> nginx[1-3] -> nginx-web` с подменой заголовка X-Forwarded-Fro

**Команда:**
```bash
curl -s -H "X-Forwarded-For: 1.2.3.4" http://localhost:8081/chain
```

**Результат:**
```json
{
    "X-Forwarded-For": "10.2.0.1, 10.2.0.10, 10.2.0.11, 10.2.0.12",
    "Remote-Addr": "10.2.0.12"
}
```
